# XT CAUSAL DOT 开发版源码基座

这是供开发者试玩、研究和二次开发的源码快照，**需要自行安装依赖、配置 DSH 和外部服务**。不是开箱即用的成品。保留手机优先的 Lite 界面、XTMEM 本地记忆引擎、知序业务核心；桌面体验尚未完整适配。界面使用系统字体，不包含原界面的字体资源。

## 包含什么

| 目录 | 内容 |
| --- | --- |
| `packages/ui` | Lite 界面和共享设置组件 |
| `packages/memory` | 记忆插件与 `vendor/xtmem` 本地 Python 引擎 |
| `packages/zhixu` | 知序业务核心及知序、飞书客户端适配 |
| `packages/runtime`、`packages/work`、`packages/postbox` | 运行时、后台工作与消息收件箱 |
| `packages/bundle/global` | 可自行修改的运行规则、角色和技能说明 |
| `packages/manual/DOT-USER-MANUAL.md` | 功能使用手册；接入外部服务后相应功能才可用 |

公开副本不包含原经典界面场景、测试用例、测试配置、测试报告、开发日志、运行数据库、会话资料、真实 API key、飞书凭证或原部署运维文件。第三方许可证保留。部分 `lib/` 文件本身就是实现源码，其他 `lib/` 文件是已有构建产物，不能将整个目录直接删除。

## 自己需要配置什么

1. **DSH 宿主和插件装配**：依赖 npm 上的 `@deepseek-ai/dsh` `0.2.1-rc.2`，不随此仓库提供 DSH 本体。自行创建 profile、配置插件及模型提供商。原实例的装配补丁未提供，不能把仓库根目录直接当作单个即插即用插件。
2. **模型服务**：自行填写兼容服务地址、模型名和 API key。密钥放环境变量或自己的密钥管理服务，不写进源码。
3. **XTMEM**：安装 Python 依赖，并配置自己的数据库路径、工作目录、actor 和 namespace。仅保留本地引擎；原云端记忆接入已移除，启用该模式会明确报错。远端服务及身份隔离需自行实现。
4. **知序和飞书**：知序业务核心需自行装配为服务；现有客户端需要兼容的服务地址和访问凭据。飞书需要自己的应用、机器人权限和桥接服务。原云端服务端、网关及飞书桥未提供。
5. **天气、搜索、语音、微信等**：各自依赖外部服务或宿主插件，需自行接入并配置。原天气接入、凭据管理、云文件插件和 MiMo 语音服务端已移除。语音界面保留客户端，需自建符合其消息协议的 WebSocket 服务，并在页面启动前设置 `window.DOT_VOICE_WS_URL` 为该服务地址。手册中的功能介绍不表示本仓库已经配好了这些服务。
6. **部署**：数据目录、访问鉴权、域名、HTTPS 和进程管理均按自己的环境设置，原服务器的部署方案及运维脚本不提供。

## 安装与构建

环境要求见 `package.json`：Node.js `^22.19.0 || >=24.0.0`，pnpm `11.9.0`；XTMEM 另需 Python 3。

```sh
pnpm install --frozen-lockfile
python -m pip install -r packages/memory/requirements.txt
pnpm run build:all
```

构建脚本按依赖顺序生成插件及远程接口。安装成功不代表已经完成服务配置，也不代表所有功能可运行。

## 已知限制

- UI 的记忆历史、恢复等调用与当前记忆接口存在差异。目前完整类型检查有 14 处错误，集中在 `packages/ui/src/client/remote-adapter.ts`：`MemoryHistoryHit`、`kind` / `visibility`、`history` / `restore`、删除确认参数等需要接手者对齐。
- 已移除经典场景的素材生成步骤，Lite 构建不再依赖该场景资源。原语音服务端已移除，语音入口需先自行配置兼容服务。
- 原部署服务被移除后，部分客户端代码保留扩展接口，需要自行实现相应后端；没有进行完整端到端验收。
- 本仓库不附带测试文件。GitHub Actions 只执行依赖安装、构建与必要语法检查，不运行原开发测试套件。完整构建遇到上述类型差异时应如实失败，CI 通过也不能代替外部服务的实际配置和验收。
